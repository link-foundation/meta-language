Meta-language needs automatic discovery of grammars and their attributed semantics so users can add languages dynamically and improve reusable Rust ↔ meta-language ↔ JavaScript translation. This is a critical requirement from the October 12, 2026 conversation, recorded in the authoritative [vision](https://github.com/link-foundation/meta-language/blob/issue-199-58f3573d6122/docs/vision.md), alongside issue #199 and PR #201. The current implementation focus remains bidirectional Rust/JavaScript translation; this issue records the discovery work separately without removing it from delivery scope.

Existing work from #93, #114, #117–#123 and `rust/src/grammar/inference/` supplies lexical inference, state merging, CFG discovery, structural priors, active learning and minimization. Audit and extend it rather than claiming this functionality is absent or complete merely because those issues were closed. JavaScript must have the same observable public behavior, with Rust generated through meta-language wherever supported.

Research baseline, verified on 2026-10-12:

- [XVada, July 2026, arXiv:2607.08959v4](https://arxiv.org/abs/2607.08959v4): evaluate its deterministic black-box inference and reported accuracy/compactness improvements against an independently reproduced baseline.
- [Crucio, January 2026, arXiv:2601.12385v1](https://arxiv.org/abs/2601.12385v1): evaluate decomposition forests and distributional lexical/grammar inference on real, larger inputs.
- [NatGI, November 2025 revision, arXiv:2509.26616v2](https://arxiv.org/abs/2509.26616v2): evaluate bracket-guided exploration and hierarchical simplification. Optional model suggestions and names are proposals; oracle checks and proof validation decide admission.
- [Attributed grammar inference, ICSME 2025, arXiv:2507.13117v1](https://arxiv.org/abs/2507.13117v1): evaluate recovering operational semantic actions from parser execution, since syntax-only discovery cannot establish translation semantics.

These are methods to compare, not evidence that any reported result already holds in meta-language. Pin research revisions, implementation commits, licenses, oracle versions, datasets and experiment configurations; record the selection rationale and rerun it when the evidence changes.

Acceptance requirements:

- [ ] Provide library and CLI discovery APIs in JavaScript and Rust. Inputs include pinned positive/negative examples, independent membership/parser oracles, optional instrumented execution traces and existing grammar sources. Diagnostics identify unsupported context sensitivity, scanner behavior and action semantics.
- [ ] Produce executable native Links Notation grammars, lossless CST structure, explicit lexer/scanner state, precedence, ambiguities, recovery and attributed semantic actions. Foreign parser/source blobs and host callbacks do not count as native operational definitions.
- [ ] Discover lexical classes, recursive structure and semantic relations generically. Preserve every source production and provenance; merge discovered grammars with official/mature grammars through the same automatic pipeline.
- [ ] Copy discovered concepts into the single global concept space. Their formal definitions recursively reference other linked concepts. Deduplicate only with checked, context-preserving one-to-one meaning certificates; equal strings, names, glosses or finite samples alone are insufficient. Preserve unresolved alternatives.
- [ ] Support deterministic seeded runs, counterexample-guided refinement, incremental updates, checkpoint/resume and source-free snapshot reload. A prepared snapshot can be restored and extended through the link-cli interface and Links Notation text or a versioned binary links representation, preserving identities, cycles, roots, CSTs and proofs.
- [ ] Demonstrate ordinary parsing and Rust/JavaScript translation after installing a newly discovered language at runtime. Mutating a linked definition changes execution on the unchanged generic runtime; stale certificates and incompatible definitions are rejected or explicitly revalidated.
- [ ] Run holdout tests, adversarial rejected examples and real project corpora under several independent oracles. Measure acceptance precision/recall/F1, CST/field/trivia/span fidelity, attributed behavior, reconstruction, grammar size, determinism, query counts, elapsed time and peak memory. Separate training from evaluation.
- [ ] Benchmark existing inference and selected recent methods under the same budgets and pinned workloads. Keep full failures and disagreement traces; choose reproducible improvements without lowering requirements or confusing statistical coverage with proof.
- [ ] Use JavaScript for development and targeted local validation. Perform Rust compilation, broad inference experiments, whole corpora and downstream workloads in CI. Maintain bounded caches and publish per-run artifacts.
- [ ] Add atomic critical requirements, public API parity mappings and executed observations to the existing source register and ledger. Update `docs/vision.md`; no competing architecture document, declaration-only completion or issue-closing directive until all required evidence is delivered.

This work follows the [associative stack](https://github.com/link-assistant/formal-ai/blob/70df98cf64c92c46e5ba7c7eb1b079521678aab0/docs/associative-tech-stack.md) and [links meta-theory](https://github.com/link-foundation/meta-theory/tree/d5923a7d0996ab4abf70bf03e9f212e3d1a8e6cc) as architectural references. Concepts, definitions, entities, relationships and multiple roots remain inspectable links; logical assumptions and scientific hypotheses stay explicitly distinguished from checked equivalence evidence.

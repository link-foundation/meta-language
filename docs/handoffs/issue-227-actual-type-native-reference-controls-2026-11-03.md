# Actual Type methods and native reference controls draft

This source draft connects the complete current `Type::map_children` and
`Type::children` method controls to the existing CI-only original/product driver.
It is not an execution report. No local tests, generation, validation or Rust
compilation ran.

The method factories capture the actual current Type, TypeField and Span CST
declarations, original annotations, method bodies, qualified owners and hashes.
Twenty-eight mapper scenarios and 23 readonly-child scenarios supply independent
literal behavior expectations. The header also checks that their constructor
inputs cover the actual current enum variant inventory. A new variant therefore
requires reconciling controls rather than silently inheriting a completion claim.

Every scenario keeps three different reference paths. The actual locked crate
method is invoked through its real public owner. Captured full serde-bearing
declarations/helpers compile independently. A separately identified serde-only
value projection compiles independently and supplies the translator frontend.
All compare their observed stdout with the same literal oracle; the projected
JavaScript and Rust products also compare with the captured full original.
These observations cover the declared method/value scenarios. They do not prove
general serialization equivalence, full module translation or every feature of
the crate.

One temporary native example bundles all actual-crate scenarios for a method,
preserving their control entry bodies and importing the actual library method.
It builds with the checkout's complete unchanged Cargo.lock, no default features
and debug information disabled. This avoids loading the unrelated default
dictionary feature in this targeted reference configuration; existing full-feature
gates remain unchanged. Original method/type source hashes are checked before and
after compilation. Captured serde references pin the exact serde release in the
project lock, require >=1 <2, and retain their own resolved lock and package list.

Every native command requires explicit CI flags. Rust and Cargo stable releases
must be >=1.90 <1.100; the 64-bit host target is recorded and explicitly passed.
Node/Links/Unicode/V8 context remains recorded. Cargo references share one uniquely
created dependency target for the run, while each executable case has its own
scratch directory. Inherited target-directory variables are removed. Temporary
examples and task-owned targets are removed; original source, generated harness,
Cargo manifests/locks, command output, captures and transport receipts remain in
the artifact directory. The actual-crate build has a separate bounded 15-minute
command allowance; ordinary commands retain their previous one-minute bound.

Failed shared source capture does not remove its scenarios. Every declared row
still attempts source derivation and downstream assertions, recording unavailable
actual predecessors as failures. Typed program and original CST text/binary
transports remain independent assertions. Projected source has its own clean CST
assertion. Scope/profile selection keeps readonly signature3 separate from the
exclusive/mutable-function profile until genuine region composition is admitted.

The JavaScript native replay producer now accepts `--group NAME`. The Rust
consumer runs every retained group separately, preserving original inputs and
per-row assertions while applying its output bound to one group at a time. The
new WeakMap/WeakSet, Symbol registry and generic weak construction rows use the
same shared compiler/machine replay. No caller is permitted to substitute native
collection contents or invent a successful product when a control is unavailable.

New weak/registry groups select their explicit Node assertion ranges before
source execution. Symbol registry input descriptors become actual native Symbol
witnesses only at the original/embedding input boundary, retaining exact source
definitions. Represented allocation and lookup do not call the host registry.

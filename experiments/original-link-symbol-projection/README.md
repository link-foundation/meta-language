# Ordered String value projection experiment

The `ordered original String value symbol projection 1` model interns an ordered
primitive String sequence after an explicit fixed dictionary. Equal UTF16 values
receive the same positive symbol, with dynamic values appended in first-observed
order. Null-name symbol zero, non-String result minus one and empty Strings stay
distinct. Complete name offset/length pairs and zero-delimited UTF16 units use the
existing certificate layout. String equality does not establish link identity,
source ownership or semantic equivalence.

The complete numeric boundary checks consecutive offsets, complete input-unit
consumption, finite integer domains, negative zero, holes, distinct fixed values
and the recorded bounds. Primitive dense-array transport remains a host premise;
the kernel does not inspect descriptors, prototypes or graph scalar owners.
Its ordered input must come from the actual checked graph traversal. Selecting
that traversal and projecting the six dynamic certificate tables remain separate
work.

The shared policy generates the entire JavaScript kernel and all 22 emitted Rust
definitions through the production parser, checker and emitter. Its immutable
array value model is explicit. Repeated scans and accumulation can be quadratic;
native execution, native adaptation and resource behavior remain unverified.

Bounded checks compare independent expected values, exact UTF16 distinctions and
all thirteen existing certificate dictionaries after text and binary reload.
An actual source rename changes the projected units. The complete checked kernel
also reloads as typed Links before JavaScript emission and execution.
